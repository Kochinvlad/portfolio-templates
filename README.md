# Витрина шаблонов сайтов

Портфолио веб-разработчика: одна витрина и четыре живых демо-шаблона, которые можно открыть
и потыкать. Кнопки не декоративные — корзина считает, фильтры фильтруют, формы проверяют ввод.

| Шаблон | Адрес | Что внутри |
|---|---|---|
| Суши и роллы | `/sushi` | Меню по категориям, поиск, корзина, промокоды, оформление доставки, таймер акции |
| Ресторан и кафе | `/restaurant` | Меню с категориями, галерея с лайтбоксом, отзывы, бронь столика с занятыми слотами |
| Интернет-магазин | `/shop` | Каталог, фильтры по бренду и цене, сортировка, избранное, чекаут в два шага |
| Магазин игрушек | `/toys` | Подбор подарка за три вопроса, фильтр по возрасту, подарочная упаковка, открытка |

## Запуск

```bash
npm install
npm run dev
```

Откроется на http://localhost:5173

Другие команды:

```bash
npm run build      # сборка в dist/ (сначала проверяет типы)
npm run preview    # посмотреть собранную версию
npm run typecheck  # только проверка типов
```

## Стек

- **React 19 + TypeScript** — компоненты и типобезопасность
- **Vite 8** — дев-сервер и сборка
- **Tailwind CSS 4** — стили через утилиты и CSS-переменные
- **React Router 7** — маршруты, каждый шаблон грузится отдельным файлом
- **lucide-react** — иконки

Бэкенда нет. Заказы и заявки никуда не уходят — это витрина, а не работающий магазин.
Состояние корзины и избранного живёт в `localStorage` браузера.

## Структура

```
src/
├── lib/            общие утилиты: типы, форматирование, хуки
├── ui/             компоненты, общие для всех шаблонов
├── store/          корзина и избранное (React Context)
├── showcase/       главная страница-витрина
└── templates/
    ├── sushi/
    ├── restaurant/
    ├── shop/
    └── toys/
```

Внутри каждого шаблона одинаковая раскладка: `data.ts` — контент, `*Template.tsx` — сборка
страницы из секций, остальные файлы — секции и модальные окна.

## Как переделать под клиента

### Тексты, товары и цены

Весь контент лежит в `data.ts` соответствующего шаблона — это обычные массивы объектов,
трогать компоненты не нужно.

```ts
// src/templates/sushi/data.ts
{
  id: 'roll-philadelphia',
  name: 'Филадельфия',
  description: 'Слабосолёный лосось, сливочный сыр, огурец и рис с нори.',
  price: 490,
  oldPrice: 590,        // необязательно: рисуется зачёркнутой
  category: 'rolls',
  glyph: '🍣',          // эмодзи для иллюстрации
  hue: 14,              // оттенок подложки, 0–360
  badge: 'Хит',         // необязательно
  weight: '240 г · 8 шт',
  rating: 4.9,
  reviews: 528,
}
```

### Цвета и шрифты

Каждый шаблон — это класс темы в `src/index.css`. Меняете переменные — меняется весь шаблон,
компоненты править не нужно.

```css
.theme-sushi {
  --brand: #e02b3c;       /* основной цвет: кнопки, акценты */
  --brand-hover: #f14656; /* он же при наведении */
  --surface: #0f0f13;     /* фон страницы */
  --surface-2: #17171d;   /* фон карточек */
  --ink: #f6f3ee;         /* основной текст */
  --ink-soft: #a29fa8;    /* второстепенный текст */
  --line: #2b2b35;        /* границы */
  --radius: 16px;         /* скругление карточек */
  --font-head: "Unbounded", sans-serif;  /* шрифт заголовков */
}
```

Шрифты подключаются в `index.html` через Google Fonts. Берите только те начертания, которые
реально используете, — каждое лишнее замедляет загрузку.

### Фотографии товаров

Снимки лежат в `public/photos` и называются по `id` товара: `roll-philadelphia.webp`.
Компонент `ProductArt` подставляет их сам — ничего прописывать в данных не нужно.

Чтобы заменить фотографию:

1. Положите свой файл в `public/photos` с именем по `id` товара (формат WebP, около 700×520).
2. Выполните `node scripts/build-photo-manifest.mjs` — он пересоберёт список доступных снимков
   и таблицу авторов в `public/photos/CREDITS.md`.

Если фотографии для товара нет или она не загрузилась, карточка не ломается: рисуется
запасная подложка с эмодзи. Так же выглядит новый товар, пока для него не подобрали снимок.

Откуда взялись текущие фотографии — в `public/photos/CREDITS.md`. Подобраны скриптом:

```bash
UNSPLASH_KEY=ваш_ключ node scripts/fetch-photos.mjs
```

Ключ Unsplash берётся из переменной окружения и в репозиторий не попадает. Запросы для
подбора — в `scripts/photo-queries.json`, точечные исправления — в `scripts/photo-fixes.json`.

Поиск иногда выдаёт не тот предмет: по запросу «power bank» приходят кабели. На такой случай
в списке можно указать конкретный снимок вместо запроса — `{ "photo": "<id на Unsplash>", "ids": [...] }`.
Так подобраны три файла из `scripts/photo-picks.json`. Скрипт пропускает уже скачанное,
поэтому для замены снимка сначала удалите его файл из `public/photos`.

**Для реального клиента фотографии берите у заказчика.** Стоковые снимки еды узнаются
с первого взгляда: гость видит на сайте суши-бара роллы не из этой кухни, и доверие падает.
Здесь они уместны только потому, что это витрина возможностей, а не сайт конкретного бизнеса.

### Превью на витрине

Карточки на главной показывают настоящие скриншоты шаблонов из `public/previews`.
Файл называется по адресу шаблона: `sushi.webp`, `restaurant.webp` и так далее.

Чтобы обновить снимок после правок дизайна:

1. Запустите `npm run dev`.
2. Откройте шаблон, прокрутите до места, которое лучше всего его показывает —
   обычно это каталог или меню с фотографиями, а не пустая шапка.
3. Скройте демо-плашку в консоли браузера, иначе она попадёт в кадр:

```js
document.querySelector('[data-demo-bar]').style.display = 'none'
```

4. Снимите скриншот видимой области и сохраните в `public/previews` под тем же именем.
   Формат WebP, ширина около 1000–1600 px, качество 80.

### Превью ссылок в мессенджерах

Когда ссылку на сайт кидают в VK, Telegram или WhatsApp, мессенджер показывает карточку:
заголовок, описание и картинку. Их задают метатеги Open Graph — сборка прописывает их
каждой странице сама (плагин `githubPagesFiles` в `vite.config.ts`):

- главная берёт заголовок и описание из `index.html`;
- шаблоны — название и описание из `src/showcase/templates.ts`;
- название сайта в карточке — константа `SITE_NAME` там же.

Картинки 1200×630 лежат в `public/og` и снимаются с настоящих страниц. После правок
внешнего вида их стоит переснять — нужен установленный Edge или Chrome:

```bash
npm run build
node scripts/build-og-images.mjs
```

Мессенджеры принимают картинку только по полному адресу. На GitHub Pages его подставляет
сборка (`VITE_SITE_URL` в `.github/workflows/deploy.yml`); на другом хостинге задайте
эту переменную сами, например `VITE_SITE_URL=https://example.ru/`.

Мессенджеры запоминают карточку ссылки. Если после обновления видна старая, добавьте
к ссылке `?v=2` — для мессенджера это новый адрес. В Telegram кэш сбрасывает бот
@WebpageBot.

### Контакты и реквизиты

Телефоны, адреса и названия вымышлены. Ищите их в футерах и шапках — они лежат прямо
в разметке секций. Ссылки `tel:` и `mailto:` в демо не срабатывают: плашка «Демо»
перехватывает нажатие и показывает подсказку, чтобы звонок не ушёл постороннему
человеку. В самих шаблонах ссылки обычные — у клиента номер будет звонить.

| Что | Где |
|---|---|
| Контакты витрины | `src/showcase/ShowcaseContact.tsx` |
| Суши | `src/templates/sushi/SushiSections.tsx`, `SushiPromo.tsx` |
| Ресторан | `src/templates/restaurant/RestaurantHeader.tsx`, `RestaurantFooter.tsx` |
| Магазин | `src/templates/shop/ShopHeader.tsx`, `ShopSections.tsx` |
| Игрушки | `src/templates/toys/ToysHeader.tsx`, `ToysSections.tsx` |

Форма «Обсудить проект» на витрине настоящая: заявки уходят на почту через сервис
[Web3Forms](https://web3forms.com). Ключ доступа — `FORM_ACCESS_KEY` в
`src/showcase/ShowcaseContact.tsx`; он публичный по замыслу сервиса и только указывает,
на какую почту слать. От спам-ботов стоит скрытое поле-ловушка `botcheck`: человек его не
видит, а бот отмечает и получает «успех» без отправки. Если сервис не ответил, форма
показывает прямые контакты и готовое письмо — заявка не теряется.

// src/templates/sushi/data.ts
export const SUSHI_PROMO_CODES = {

## Добавить новый шаблон

1. Заведите тему в `src/index.css` — скопируйте любой блок `.theme-*` и поменяйте переменные.
2. Создайте папку `src/templates/<название>/` с файлами `data.ts` и `<Название>Template.tsx`.
3. Оберните шаблон в провайдеры, если нужна корзина:

```tsx
<CartProvider storageKey="myshop" deliveryFee={300} freeDeliveryFrom={3000}>
  <div className="theme-myshop min-h-screen bg-surface text-ink">
    <ToastProvider>{/* секции */}</ToastProvider>
  </div>
</CartProvider>
```

`storageKey` должен быть уникальным — иначе корзины разных шаблонов смешаются в `localStorage`.

4. Добавьте маршрут в `src/App.tsx` (через `lazy`, как остальные).
5. Добавьте карточку в `src/showcase/templates.ts` — она появится на витрине.
6. Снимите картинку для превью ссылки: `npm run build && node scripts/build-og-images.mjs`.
   Без неё сборка предупредит, а карточка ссылки выйдет без изображения.

Готовые кирпичики в `src/ui/`: `Button`, `Modal`, `Drawer`, `CartPanel`, `Input`, `Select`,
`Textarea`, `OptionCards`, `QtyStepper`, `Rating`, `Badge`, `EmptyState`, `IconButton`,
`ProductArt`, `Section`, `SectionHeading`.

## Деплой

Сайт статический — сервер не нужен, только раздача файлов. Платить придётся лишь за домен
(примерно 200–1500 ₽ в год), да и то не сразу.

Проект настроен под GitHub Pages, но собранная папка `dist/` подходит и любому другому
статическому хостингу.

### GitHub Pages — настроено, работает из России

Публикация идёт автоматически: каждый `git push` в ветку `main` запускает сборку и выкладывает
сайт. Настройки — в `.github/workflows/deploy.yml`.

Первый запуск:

1. Создайте на GitHub пустой публичный репозиторий (без README и .gitignore — они уже есть).
2. Привяжите его и отправьте код:

```bash
git remote add origin https://github.com/ВАШ_НИК/ИМЯ_РЕПОЗИТОРИЯ.git
git branch -M main
git push -u origin main
```

3. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
4. Через пару минут сайт будет на `https://ВАШ_НИК.github.io/ИМЯ_РЕПОЗИТОРИЯ/`
   Ход сборки виден во вкладке **Actions**.

Что уже сделано под Pages и почему:

| Что | Зачем |
|---|---|
| `base` из переменной `VITE_BASE` в `vite.config.ts` | Сайт лежит не в корне домена, а в подпапке с именем репозитория — иначе стили и скрипты не найдутся |
| `basename` у `BrowserRouter` в `src/main.tsx` | Чтобы маршруты совпадали с этой подпапкой |
| Папка на каждый маршрут с копией `index.html` | GitHub Pages не умеет переписывать адреса, зато отдаёт `index.html` из папки — прямой заход на `/sushi` возвращает статус 200, страницу видят поисковики и мессенджеры |
| `404.html` — та же копия | Страховка для всех прочих адресов: загрузится приложение и покажет свою страницу «не найдено» |
| `.nojekyll` | Иначе Jekyll игнорирует файлы и папки, начинающиеся с подчёркивания |

Имя репозитория подставляется в сборку само, менять конфиг при переименовании не нужно.

Проверить сборку для Pages локально:

```bash
MSYS_NO_PATHCONV=1 VITE_BASE=/ИМЯ_РЕПОЗИТОРИЯ/ npm run build
```

`MSYS_NO_PATHCONV=1` нужен только в Git Bash на Windows — без него он подменяет значение
переменной на путь внутри установки Git. В PowerShell пишите `$env:VITE_BASE="/имя/"` отдельной
строкой, в CI это не нужно вовсе.

### Важно про маршруты

Маршруты обрабатывает React Router в браузере — на сервере файла `/sushi` не существует.
Поэтому при прямом заходе или обновлении страницы хостинг должен отдавать `index.html`
вместо ошибки. Во всех трёх вариантах это уже решено:

| Хостинг | Чем решается |
|---|---|
| GitHub Pages | папка с `index.html` на каждый маршрут плюс `404.html`, создаются при сборке |
| Vercel | правило `rewrites` в `vercel.json` |
| Netlify | `netlify.toml` и `public/_redirects` |

Если будете разворачивать где-то ещё — на nginx, Apache или обычном хостинге, — настройте
такое же правило вручную, иначе работать будет только главная страница.

## Что здесь демо, а что по-настоящему

**Работает по-настоящему:** корзина с подсчётом, промокоды, фильтры, поиск, сортировка,
избранное, проверка форм, модальные окна, галерея, подбор подарка, адаптив, сохранение
корзины между перезагрузками.

**Имитация:** отправка заказов и броней в шаблонах. Форма ждёт 700–800 мс и показывает
экран успеха — никаких запросов на сервер не уходит. Ищите в коде комментарии
`// Демонстрация:`. Звонки и письма по ссылкам в шаблонах тоже не уходят — см. «Контакты
и реквизиты». Форма заявки на самой витрине — настоящая.

## Что дальше

Витрина показывает фронтенд. Следующий шаг, который заметно поднимает ценность портфолио, —
бэкенд:

- приём заказов в Telegram-бот или на почту;
- база заказов и админка для клиента;
- личный кабинет и история заказов;
- оплата через ЮKassa или CloudPayments.

Компоненты уже разделены на «данные» и «отображение», поэтому подключение API не потребует
переписывать разметку: вместо импорта из `data.ts` появится запрос к серверу.

## Лицензия и оговорка

Код можно использовать как угодно. Все компании, адреса, телефоны, цены и отзывы в шаблонах
вымышлены — это демонстрационный материал, а не реальные организации.
